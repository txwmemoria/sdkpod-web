sw

跨机器验证与 AI 上下文同步

在 Windows / macOS / Linux 两台对等机器上开发同一项目时，用一条命令把未提交改动送到对端编译测试，并把 Claude 等本地 AI 会话一并带走。无需先 push，也不碰对端工作区。基于 iroh：局域网直连，跨网走加密中继。

它解决什么

一、想知道代码在另一台机器上能不能编过、测过。

常见流程是：提交 → 推送 → 切机器 → 拉取 → 跑构建。往往只是几行改动，也要走完整套。

二、换机器之后，本地 AI 会话断了。

Claude Code 的对话和记忆在本机（~/.claude/）。代码能靠 git 过去，这些不能。

sw 各变成一条命令：

你想做的命令
让对端编译并测试当前工作区（不必提交）sw verify
把 AI 会话与记忆带到另一台机器sw ctx
提交完，让对端跟上这个分支sw handoff
哪里不通，一次查清sw doctor
本机、对端、项目与 verify 历史sw tui

两台机器对等，任意一方都能发起。不要求同一局域网：能上网即可互通；同网或 VPN 时会尝试直连。

sw verify 长什么样

在 Windows 上发起，Mac 编译——改动没有 commit，也没有 push：

verify mac-mini  verify  f3f2730 + 1 file
  on mac-mini (macos)  /Users/me/projects/app
  › reusing worktree
  › applying patch
  › [1/2] cargo build --release --all-targets
error[E0308]: mismatched types
 --> src/style.rs:106:18
fail mac-mini exit 1 in 1.6s

三件关键事：

  1. 当前工作区（含未暂存、未跟踪）打成 patch 直接送到对端。
  2. 对端诊断原样回到你的终端，带着文件与行号。
  3. 退出码是对端的——可接进 &&、hook，或「改 → 远端验 → 再改」的循环。

首次冷缓存约一分钟级；之后常在 1.6s 量级——对端保留持久 worktree 与构建缓存，远端验证能进内层开发循环。

从零到能用

需要 Rust 1.91+ 与 git。配对与节点每台机器一次；每个仓库再接入一次。

1. 安装（两台都装）

cargo install --git https://github.com/txwmemoria/sync-work --locked

--locked 不要省，否则两边可能解析出不同依赖版本。

2. 配对（一次）

# 机器 A
sw pair init          # 复制 sw1:…

# 机器 B
sw pair join sw1:…    # 再把回执 ticket 拷回 A

# 机器 A
sw pair join sw1:…
sw pair list

ticket 只有公钥、机器名与平台——一次配对覆盖之后所有项目。

3. 开机自启节点

sw service install

macOS / Windows / Linux 用户级自启，不需要管理员。节点负责接收对端的 verify / ctx。

4. 接入仓库

# 机器 A
sw init               # 生成 syncwork.toml，提交它

# 机器 B（同一项目的克隆）
git pull && sw link

路径可以不同；靠项目名对应。需要 AI 上下文时两边再跑 sw hook install，最后 sw doctor 应显示通过。

日常用法

sw verify                 # 跑名为 verify 的配方
sw verify check           # 换配方
sw verify --peer mac      # 多台时指定对端
sw ctx                    # 双向同步当前项目的 AI 上下文
sw ctx --watch            # 长会话挂着同步
sw handoff                # push，并在安全时快进对端
sw status
sw tui

记忆口诀：代码内容跟着 patch 走，配置文件跟着 git 走。 改了 syncwork.toml 要用 sw handoff（或自行 push）让对端拿到新配方。

同一 Claude 会话请同一时间只在一台机器上聊；两边同时 /resume 会分叉——两边文件都会保留。Markdown 记忆文件会尽量三方合并。
